# analysis/test_design.md

## Собственные тестовые случаи

### Тест 1. Демонстрация пользы навыка (EXP-TEST-01)

**Что именно проверяется:** Способность выявлять неочевидную двойную утечку при аугментации данных, когда формально «точных дублей строк нет», но аугментированные версии одного исходного снимка одного пациента оказываются по разные стороны разбиения.

**Почему этот случай важен:**
- Аугментации воспринимаются практиками как безопасная стандартная практика, поэтому момент их применения относительно разбиения часто не описывается.
- Нарушение двойное: DUPLICATE_LEAKAGE (аугментации одного снимка в train и test) + GROUP_LEAKAGE (разные снимки одного пациента в обеих выборках при заявленной цели «оценка на новых пациентах»).
- Высокая метрика (AUC=0.94) маскирует проблему — без навыка её легко пропустить.

**Протокол теста:**

- **id:** EXP-TEST-01
- **title:** Аугментация медицинских снимков
- **goal:** Классифицировать патологии на рентгене грудной клетки для новых пациентов
- **protocol:** Исходный датасет: 5000 снимков от 2000 пациентов (по 1–4 снимка на пациента). Применена аугментация (повороты на ±15°, горизонтальные отражения, лёгкое изменение яркости), увеличившая датасет до 15000 изображений. Разбиение 80/20 выполнено случайно по изображениям. Нормировка настроена только на train. Модель выбрана по validation AUC, финальный test использован один раз.
- **report:** Test AUC=0.94. Команда утверждает, что оценка независима, так как аугментации — стандартная практика и точных дублей строк в выборках нет.

**Ожидаемое поведение модели:**

- **verdict:** FAIL
- **flags:** DUPLICATE_LEAKAGE, GROUP_LEAKAGE
- **evidence:** Аугментированные версии одного и того же снимка (повороты, отражения) с высокой вероятностью попали по разные стороны случайного разбиения по изображениям. Кроме того, разные снимки одного пациента также могут оказаться и в train, и в test, что противоречит заявленной цели — оценке на новых пациентах.
- **next_step:** Выполнить разбиение на уровне пациентов (group split), чтобы все снимки и их аугментации одного пациента попадали только в одну выборку. Аугментации применять после разбиения, внутри train-пайплайна.

**Какие ошибки позволяет выявить проверка:**
- Ложный PASS, если навык ориентируется только на отсутствие «точных дублей строк».
- Пропуск GROUP_LEAKAGE, если навык не связывает цель «новые пациенты» с необходимостью группового разбиения.
- Игнорирование DUPLICATE_LEAKAGE из-за того, что аугментации технически создают новые пиксельные массивы.

### Тест 2. Демонстрация ограничения навыка (EXP-TEST-02)

**Что именно проверяется:** Граница применимости навыка — ситуация, где в протоколе есть реальная методологическая слабость, но она не попадает ни в одну из категорий политики. Навык должен корректно поставить PASS, не «додумывая» нарушений.

**Почему этот случай важен:**
- Показывает, что навык — не замена полноценному ML-ревью. Он проверяет конкретный закрытый перечень нарушений, а не общее качество эксперимента.
- Предотвращает ложные срабатывания: если навык начнёт flagged всё, что «выглядит подозрительно», его ценность как формального аудитора упадёт.
- Демонстрирует корректную работу правила «Отсутствие описания ≠ доказанное нарушение».

**Протокол теста:**

- **id:** EXP-TEST-02
- **title:** Прогноз спроса с редким событием
- **goal:** Прогнозировать недельный спрос на товары в интернет-магазине
- **protocol:** Временной holdout: обучение на данных 2023–2024 годов, тест на первом квартале 2025 года. Признаки: исторические продажи за 8 недель, цена, факт промо-акции, температура воздуха. Все признаки доступны на момент прогноза. Target encoding категорий товаров обучается внутри CV-фолдов. Финальный test использован один раз. Метрика: MAE.
- **report:** Test MAE=12.4 единицы. В тестовом периоде прошла акция Black Friday, которой не было в обучающей выборке. Команда отмечает, что MAE в недели акции значительно выше среднего, но считает эксперимент методологически корректным.

**Ожидаемое поведение модели:**

- **verdict:** PASS
- **flags:** (пусто)
- **evidence:** Временной holdout корректен для задачи прогнозирования будущего. Все признаки доступны на момент прогноза. Target encoding обучается внутри CV-фолдов, не видя validation/test target. Финальный test использован один раз. Формальных нарушений из перечня политики не обнаружено.
- **next_step:** Зафиксировать seed, версию данных и гиперпараметры для воспроизводимости. Дополнительно: рассмотреть добавление в обучающую выборку исторических данных по аналогичным редким событиям (прошлые Black Friday) или внедрить отдельную модель для пиковых периодов, чтобы снизить MAE в такие недели.

**Какие ошибки позволяет выявить проверка:**
- Ложный FAIL по SHIFT_UNVALIDATED: Black Friday — редкое событие из того же генерального процесса, а не «смена распределения» в смысле политики (датчики/процесс не менялись).
- Ложный FAIL по METRIC_MISMATCH: MAE честно отчитан, команда сама отмечает проблему в подпериоде — это не маскировка.
- Ложный NEED_INFO: факт отсутствия Black Friday в обучении прямо указан в протоколе, уточнять нечего.
- Переход границы компетенции: попытка flagged проблему устойчивости/качества модели, которая вне scope 01_audit_policy.md.

## Связь с результатами на practice.json

Оба собственных теста дополняют картину, полученную на practice.json:

- **TRAIN-14-01** (FAIL, GROUP_LEAKAGE) — простой случай, где нарушение прямо описано в протоколе. **EXP-TEST-01** усложняет эту ситуацию: нарушение есть, но замаскировано под «стандартную практику аугментации».
- **TRAIN-14-02** (PASS, IID-изображения) — простой случай корректного протокола. **EXP-TEST-02** усложняет ситуацию: протокол формально корректен, но содержит реальную практическую слабость, которую навык должен **не** flagged.

Таким образом, собственные тесты проверяют навык на пограничных случаях, которые не покрываются учебными примерами из practice.json, но критичны для реальной эксплуатации аудитора.
